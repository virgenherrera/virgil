# Glossary

← [Index](README.md)

> Definitions of the specialized terms used by the idea-to-mvp framework.
> Ordered alphabetically. Canonical names use the English camelCase
> convention.

---

| Term | Definition |
|------|------------|
| **AAA** (Arrange-Act-Assert) | Mandatory structural pattern for every test. Three separate blocks: prepare state, execute operation, verify result. If a test needs more than one Act, it is two tests. |
| **Abort + Replan** (interruption strategy) | Strategy of the interruption protocol for when the bug invalidates assumptions of an upstream artifact (schema, contracts, security). Cascades `approved → draft` across the affected artifacts; the branch is preserved for cherry-pick after the replan. See [fastForward — Interruption Protocol](planning/behavior/fast-forward.md#interruption-protocol-mid-implementation). |
| **abuseCases** | Adversarial counterpart to positive ACs. For every AC with data input, the testPlan must include cases for empty, corrupted, or invalid payloads, injections (SQL, NoSQL, XSS, prompt), undeclared extra fields, and authentication/authorization abuse. complianceByDesign. |
| **AC** (Acceptance Criterion) | Acceptance criterion in given/when/then format that defines when a requirement is considered met. |
| **accept** | Final gate of every execution iteration where QA certifies that the product meets what is stipulated in the handoff. It does not validate code — it validates the product against the contract. |
| **adapter** | Pluggable implementation of the artifactStore's universalInterface (local, engram, hybrid, DBMS, etc.). |
| **ADR** (Architecture Decision Record) | Record of an architectural decision with context, evaluated alternatives, and justification. Part of `design.md`. |
| **appTest** | Test that exercises the real application stack with no mocks. Boundary = the app. The framework's primary tier. Detects droppableCode via mandatory high coverage. |
| **artifactStore** | Persistence layer where planning artifacts live. Outside the target repo. Accessible via a 9-operation universalInterface. |
| **bindingLayer** | Layer maintained by the TPM: tracks traceability between artifacts — which AC in `spec.md` is covered by which task in `tasks.md`, which task has at least one associated test. It is link accounting: it confirms that the link exists, not that it is high quality. Link strength is measured by external tools (mutationTesting, CRAP score, cyclomatic complexity) via metricsOrchestration. Dogma, principle 2. |
| **boundaryModel** | Criterion that determines the type of test based on where the mock boundary sits: File (unit, forbidden), Module (integration, derived), App (service/component, explicit development), Solution (E2E, explicit development). Organizing axis of the Red Phase. |
| **buildArtifact** | Output generated by the echo: compiled artifacts, coverage reports, API documentation, etc. Lives in a gitignored folder within the repo (or a remote registry for cloud artifacts). Not to be confused with planning artifacts (idea.md, spec.md, etc.), which live in the artifactStore. See [artifact system](artifact-system.md). |
| **builderPattern** | Pattern for building test data via reusable factories. Centralizes data creation and allows varying only what is relevant to the case. Avoids hardcoded data in the test body. |
| **bumpDependencies** | Automation enabled by the deterministic echo. Pattern: bump dependencies → run the full echo → if green → automatic commit. Addresses the tension between pinned versions and modern dependencies. The concrete mechanics are ported to the project's platform. See [echo system](echo-system.md). |
| **circuitBreaker** | Protection mechanism: if 3 consecutive delegations to the same role fail, the SM stops the chain and escalates to the MIM. |
| **claiming** | Coordination mechanism in parallel execution: a subAgent marks a DAG task as `claimed` before working on it, preventing another subAgent from taking it. Part of `handoff.md`'s executionState. Dogma, principle 5. |
| **compactRules** | Project code rules and conventions, extracted from the skill registry, that the orchestrator injects pre-digested into each subAgent. |
| **complianceByDesign** | Framework principle: if tests strictly assert DTOs, include abuseCases, and verify structuralCompliance (persistence, frontend, IaC), verification of the DATA LAYER of regulatory compliance (HIPAA, PCI DSS, GDPR, SOC 2, WCAG, ADA) is obtained as a side effect — without additional suites or rewrites. It does not cover the organizational, physical, legal, or procedural controls of each regulation. |
| **compositeAgent** | subAgent that sequentially assumes multiple personalities within a worktree: testEngineer (Red) → Implementor (Green) → mechanical verification via fitnessFunction (Refactor), where it runs the fitness functions and documents residualReview observations. Used in parallel execution to avoid filesystem conflicts. |
| **contractArchitect** | Execution role that defines formal contracts (APIs, schemas, interfaces) from the handoff. Active in prePhase. |
| **contractCollision** | Conflict between contracts (typically database migrations) declared by two concurrent cycles during the prePhase Contracts stage. The SM serializes it: one cycle proceeds against the current baseline, the other replans its migration against the new baseline. Logged with the `[COLLISION]` tag. See [contracts.md](execution/contracts.md#contract-collision-between-concurrent-cycles). |
| **CRAP score** (Change Risk Anti-Patterns) | Metric combining cyclomatic complexity and test coverage: complex, poorly tested code gets a high (risky) score. Calculated by external tools (crap4j and equivalents) and consolidated by Virgil via metricsOrchestration. |
| **cyclomaticComplexity** | Number of independent decision paths in a function/method. Feeds the CRAP score and, in Dogma, is ADDITIONALLY verified as an independent fitnessFunction with its own per-tier threshold — a method can have a low CRAP score due to good coverage and still be too complex. Calculated by external tools (gocyclo, eslint `complexity`, radon) via metricsOrchestration. |
| **DAG** (Directed Acyclic Graph) | Dependency graph between tasks in `tasks.md`. Defines execution order and parallel lanes. |
| **delegationContract** | Structure with mandatory fields (role, personality, context, input, output, constraints, status report) that the SM uses to launch a subAgent. |
| **dependencyStructure** | Direction of dependencies between modules/layers: detects cycles and violations of the dependency rule (inner layers do not depend on outer ones). Mechanical verification of what the Architecture reviewer role used to cover — zero tolerance across all tiers. Calculated by external tools (go vet, eslint-plugin-import, dependency-cruiser, ArchUnit) via metricsOrchestration. |
| **deterministicGate** | Transition point between phases that is validated mechanically (e.g. `virgil handoff lint`, `virgil health` thresholds) instead of by subjective approval. Dogma, principle 6: the agent operates under constraint, not under trust. |
| **droppableCode** | Code with 0% appTest coverage. If no test touches it through real product interactions, it has no justification to exist. Candidate for removal. |
| **E2E** (End-to-End) | Test that exercises the full deployed solution, multi-service, with zero mocks. Boundary = the solution. The framework's second explicit tier. Runs on deploys, tags, and merges to main/develop. |
| **echo** | Deterministic 5-step sequence (Setup → Build → Static Test → Dynamic Test → E2E Test) that runs in every environment (dev, QA, CI, CD) in the same order but with variable scope. Guarantees structural homogeneity across environments. The echo is mandatory (TINA). See [echo system](echo-system.md). |
| **environmentParityCheck** | RECOMMENDED (not TINA) check that compares runtime configuration, declared env vars, and infrastructure flags between staging and production, as part of the deployment gate. Virgil does not manage infrastructure, it can only orchestrate the check. See [Environment Homogeneity](echo-system.md#environment-homogeneity) and the environment parity note in [phases.md](planning/behavior/phases.md). |
| **escapeHatch** | Third path of imperativeMode: the SM executes a direct MIM request without going through the phase chain when it is mechanical, low-risk, and deterministic (estimated F1-F4 score of 7-8). Logs `[IMPERATIVE]`. Never applies to contracts, public APIs, database schemas, or security boundaries; when in doubt, the SM uses the guide path instead. See [phases.md](planning/behavior/phases.md#imperative-mode--sm-response-to-direct-requests). |
| **execution** | Framework Mode 2. Transforms the handoff into functional code through the red/green/refactor cycle + accept. Operates on the repository's working tree. |
| **executionState** | Per-task execution status within `handoff.md`, independent of the artifact's approval status. Values: `pending` (available), `claimed` (taken by a subAgent), `done` (completed and verified). Enables parallel execution on a single handoff (claiming). Dogma, principle 5. |
| **executionOrchestrator** | Execution coordinator. Analogous to planning's SM but operates on the repository's working tree, not the artifactStore. Delegates, does not execute. |
| **[EXTERNAL]** (tag) | Log marker the SM persists in the affected artifact's `history()` when it detects an externalChange. Analogous to `[INTERRUPTION]`, `[HOTFIX]`, and `[IMPERATIVE]`. See [recovery.md](planning/behavior/recovery.md). |
| **externalChange** | Commit detected by the SM that was not produced by the current cycle (no `[IMPERATIVE]`/`[HOTFIX]` tag, no corresponding `claimed` task in executionState). Classified as `additive`, `contradicting`, or `other_cycle` and logged with the `[EXTERNAL]` tag. |
| **externalContractDrift** | Critical semanticDrift (`SEMANTIC_DRIFT_CRITICAL`) originating from a breaking change in a third-party API's contract (deprecated endpoint, new required field) — it does not originate within the idea → spec → design → tasks chain, but triggers the same cascade as internal drift (blocks approval, re-delegates to `design.md`). A backward-compatible change is classified as minor drift and absorbed without cascading. See [state-machine.md](planning/artifacts/state-machine.md#semanticdrift-detection). |
| **fastForward** | Mechanism that lets the SM advance multiple phases when the certainty gradient (F1-F4) is high. Applies at the start and mid-cycle. |
| **fitnessFunction** | Mechanical tool that verifies a quality dimension (cyclomaticComplexity, dependencyStructure, moduleSize, mutationTesting, CRAP score) against a per-tier threshold, without subjective code reading. Replaces the reviewer role in the Refactor Phase. Dogma, principle 3: "you don't review the agent's code, you measure metrics". |
| **gate** | In planning: validation point where an artifact must reach `approved` to unlock the next phase. In execution: operational checkpoint (tests pass, coverage meets threshold, QA certifies). |
| **handoff** | Artifact (`handoff.md`) that acts as a self-contained contract between planning and execution. Portable and bounded. |
| **handoffLint** | Command (`virgil handoff lint`) that mechanically validates that `handoff.md` is self-contained, references existing artifacts, and meets the minimum schema, before enabling execution to start. deterministicGate at the planning → execution transition. |
| **highValueTesting** | Framework philosophy: only tests that exercise REAL product interactions add value. Tests with extensive mocking give false confidence. |
| **Hold** (interruption strategy) | Interruption protocol strategy for a bug independent of the current scope: a dedicated parallel cycle is opened and the work in progress remains untouched. Logged as `[INTERRUPTION]` in `idea.md`/`plan.md`. See [fastForward — Interruption Protocol](planning/behavior/fast-forward.md#interruption-protocol-mid-implementation). |
| **[HOTFIX]** (tag) | Log sub-item for a Stowaway fix (≤1 task, no contract changes) that travels within the current cycle's PR or handoff, preserving traceability. |
| **[IMPERATIVE]** (tag) | Log marker for interactions under imperativeMode (reject, guide, or escapeHatch paths), persisted in `idea.md`/`plan.md` with the SM's reasoning. Analogous to `[INTERRUPTION]` and `[HOTFIX]`. |
| **imperativeMode** (Imperative Mode) | The SM's response to an imperative MIM request that skips the phase chain ("just do X"). Evaluates domain and risk and resolves via one of three paths: (a) reject (security, data integrity, regulated domains), (b) guide — default, 2-3 targeted questions followed by Light Tier fastForward — or (c) escapeHatch. Every interaction is audited with the SM's reasoning. See [phases.md](planning/behavior/phases.md#imperative-mode--sm-response-to-direct-requests). |
| **implementor** | Execution role that writes code to pass the tests. Active in the Green Phase. Pragmatic, no premature perfectionism. |
| **[INTERRUPTION]** (tag) | Log marker the SM writes to `idea.md`/`plan.md` documenting the chosen strategy in response to an interruption (Hold, Stowaway, or Abort + Replan) and its reasoning. Mandatory gate of the interruption protocol. See [fastForward](planning/behavior/fast-forward.md#interruption-protocol-mid-implementation). |
| **lane** | Parallel branch in the task DAG that can run concurrently with others. |
| **lastVerifiedAt** | Per-artifact timestamp, maintained by the TPM, updated on every successful `verifyConsistency` run against that artifact. The SM checks it during Recovery to determine whether a later commit touches the artifact's file scope; if so, the TPM marks the artifact as `stale`. Does not replace the Recovery protocol — it complements it by avoiding unnecessary re-verification. See [recovery.md](planning/behavior/recovery.md#lastverifiedat--avoiding-unnecessary-re-verification). |
| **metricsOrchestration** | Virgil's responsibility to invoke specialized, language-specific external tools (mutationTesting, CRAP score, cyclomatic complexity) and consolidate their results into `virgil health`. Virgil orchestrates, it does not implement its own analysis engines — keeping the framework language-agnostic. See [echo system](echo-system.md). |
| **MIM** (Mind behind the Idea and the Money) | The human who directs the project. Decides, approves, and unblocks. The final decision-making node. |
| **miniPDC** | Abbreviated version of the PDC. Applied when the delegation is low-risk and the result is mechanically verifiable. |
| **moduleSize** | Lines of code per file/module. Mechanical proxy for single responsibility at the module level when it grows unbounded. Per-tier threshold (see [refactor.md](execution/refactor.md#thresholds-per-tier)). Calculated with language-agnostic tools (cloc, `wc -l`, the stack linter's `max-lines` rules). |
| **multiCycleInteractionTesting** | Advisory (non-blocking) verification recommended in Accept when two active cycles with feature flags share overlapping file scope: integration testing with both flags enabled, to detect interactions that no individual cycle covers. Does not block certification of each cycle separately. See [accept.md](execution/accept.md#multi-cycle-interaction-testing-feature-flags). |
| **mutationTesting** | Technique that introduces deliberate mutations into the code and checks whether the test suite detects them. Measures actual test strength, beyond line coverage. Orchestrated by Virgil (metricsOrchestration) via external tools (Stryker, PIT, mutmut, cosmic-ray). |
| **operation** | Framework Mode 3. Optional and reactive mode where the MIM becomes a user of the product and the agent becomes the operationalAssistant. No phases or ceremony. Activated only if the project has an operational surface. |
| **operationalAssistant** | Agent's role in operation. Executes what the user requests within the context of the built project. Does not plan or build — it operates. |
| **opsRunbook** | Artifact (`ops-runbook.md`) that documents operation, monitoring, troubleshooting, and escalation for projects with live services. Backed by ISO 20000 + ITIL 4. |
| **patternA** | Retrieval strategy where the SM searches, curates, and re-injects context into the subAgent's prompt. Useful for fuzzy searches or high fan-out (8+). |
| **patternB** | Retrieval strategy where the SM passes only topic_keys and the subAgent queries the artifactStore directly. 6x cheaper than patternA. |
| **PDC** (Post-Delegation Checkpoint) | 4-step protocol the SM runs after every subAgent return: ECHO (coherence), VERIFY (coverage), MARK (persist), DECIDE (next action). |
| **pivot** | Requirements change that alters the scope, direction, or ACs of work in progress. The framework treats it as a legitimate operation (not an error). Three categories: localized (AC modified), structural (stack/approach changes), fundamental (product direction changes). The SM assesses impact and selectively regenerates the affected artifacts. |
| **planning** | Framework Mode 1. Transforms the idea into a validated handoff through planning phases, approval gates, and the artifactStore. |
| **POM** (Page Object Model) | Pattern for tests with an interface (UI, CLI). Abstracts mechanical interactions into reusable objects. The test describes intent, the POM executes the mechanics. |
| **postDeployRollback** (Post-Deploy Rollback Protocol) | The SM's handling when an already-deployed and certified change fails in production while a dependent change is in progress. The dependent change is treated as Abort + Replan; the reverted change re-enters Phase 6 (Verify) with new test cases covering the production gap, and Phase 8 Retrospective becomes mandatory. See [phases.md](planning/behavior/phases.md#post-deploy-rollback-protocol). |
| **prePhase** | First stage of execution. Defines formal contracts before writing tests or code. Enables parallel development. |
| **QA** | Execution role active in accept. Verifies the product against the handoff. Does not write tests or fix code — it certifies. Certification mechanism defined by the framework's consumer. |
| **RAG** (Retrieval-Augmented Generation) | The artifactStore used as a bounded context source for agents. Agents query specific slices, not the full codebase. |
| **red** / **green** / **refactor** | The 3 macro phases of execution. red = write tests (they fail). green = write code (tests pass). refactor = mechanical quality verification via fitnessFunction (tests keep passing). |
| **residualReview** | Exception to the mechanical Refactor gate: findings that are not mechanizable by a fitnessFunction (business-logic security, DDD modeling). Documented but do not block the automatic gate; escalated on demand, not as the phase's default mechanism. |
| **reverseBinding** (inverse binding / reverse traceability) | Inverse path of the bindingLayer: from an already-written code file back to the task, design decision, and business problem that originated it (file → task → design → spec → idea). Resolved through three complementary mechanisms: the binding annotation (the workItem's `files` field, confirmed in the Green Phase), git integration (commits reference the task ID), and the inverse query (`verifyConsistency` in `--reverse` mode). Traceability lives in artifacts and git, never in code comments. See [Reverse Traceability](planning/artifacts/README.md#reverse-traceability--code-to-artifact). |
| **reviewer** | Execution role active in refactor under Dogma v1. **Deprecated in Dogma**: a sub-agent that reads code and produces a review report is still relocated code review, which principle 3 explicitly forbids. Replaced by fitnessFunction (mutationTesting, CRAP score, cyclomaticComplexity, dependencyStructure, moduleSize); what is not mechanizable persists as residualReview. |
| **schemaStrictAssertions** | Test discipline rule: every assertion on response objects verifies the FULL shape of the DTO (fields present, fields absent, types). Detects extra fields that could violate regulatory compliance. |
| **semanticDrift** | Misalignment between a downstream artifact and its upstream after the upstream was modified. Detected by `verifyConsistency`. |
| **SM** (Session Manager / Orchestrator) | The main agent that acts as the project's facade. Orchestrates phases, convenes roles, validates gates, and controls transitions. Does not produce content. Not a Scrum Master in the Scrum Guide sense. |
| **smProcess** | Specialized subAgent the SM instantiates to extract process rules from project files (e.g., a challenge's rules). Instantiated on demand, not a permanent role. |
| **spike** | Time-boxed exploration that produces disposable code (droppableCode by definition) to answer technical questions blocking planning. Authorized by the MIM, run on a disposable branch (`spike/{name}`). Output: findings that feed `idea.md` or `spec.md`. Reduced echo (Setup + Build only). |
| **stale** (artifact) | Status the TPM assigns to an artifact when its lastVerifiedAt predates a later commit touching files in its scope. Requires re-verification (`verifyConsistency`) before continuing the cycle. |
| **Stowaway** (interruption strategy) | Interruption protocol strategy for a fix of ≤1 task that does not change contracts: it travels within the current cycle's PR/handoff as a sub-item, tagged `[HOTFIX]`. `verifyConsistency` must watch that it does not contaminate the PR's declared scope. See [fastForward — Interruption Protocol](planning/behavior/fast-forward.md#interruption-protocol-mid-implementation). |
| **structuralCompliance** | Tests that verify the STRUCTURE of each architectural layer, not its behavior. Three conditional dimensions (activated only if the project has them): persistence (schema, hashing, encryption), frontend (A11y, i18n, responsive), infrastructure (exact versions, validated env vars, fail-fast). Tagged as `structural`, run in CI. |
| **subAgent** | Agent instantiated by the SM with a bounded delegationContract. Receives a specific personality, context, and constraints for its task. Team roles are subAgents. |
| **testContract** | Enumerable manifest per subject under test. Each entry links a test case to an immutable name traceable to an AC. Prevents spaghetti test code. |
| **testEngineer** | Execution role that writes the test suite mapped to ACs and contracts. Active in the Red Phase. Skeptical, prioritizes appTests (real stack) over any form of mocking; unit forbidden, integration derived by filtering. |
| **testImplementation** | Executable tests that reference the testContract. Includes appTests (real stack, no mocks) and E2E tests (deployed solution). All must fail at the end of red (no implementation yet). |
| **testPlan** | Meta-document that maps ACs to test cases, assigns boundaries (App/E2E), and tags tests for filtering (smoke, critical, regression). |
| **tier** | Framework ceremony level (Light, Standard, Full). The SM determines the tier using the F1-F4 score. Tiers scale ceremony; in the Light tier, artifacts can be compressed into a single document (`plan.md`) while keeping the ISO content sections. Dogma reuses the same concept for quality thresholds in `virgil health`: the `strict`, `standard`, `relaxed`, and `custom` profiles define how demanding the traceability and strength thresholds (mutationTesting, CRAP score, complexity) are for that project — a `relaxed` tier does not require the same score as a `strict` tier. |
| **TPM** (Technical Program Manager) | Infrastructure agent that acts as the artifactStore's DBMS. The only actor that writes to the store. Validates integrity, format, and completeness with editorial judgment. |
| **transition()** | Adapter operation that changes an artifact's state in the state machine (draft, review, approved, rejected, cancelled). |
| **universalInterface** | The 9 operations every artifactStore adapter must implement: `ingest`, `save`, `read`, `search`, `list`, `delete`, `verifyConsistency`, `history`, `transition`. |
| **workItem** (L0-L4) | Work decomposition hierarchy: L0 (Initiative), L1 (Feature), L2 (Requirement), L3 (Activity), L4 (Sub-activity). Defined in `tasks.md`. |
| **worktree** | Git mechanism that creates an isolated working directory with its own branch. The executionOrchestrator uses them to run parallel lanes without file conflicts. |
